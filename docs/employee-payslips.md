# Employee Payslips — Production Employee Experience

## Production integration

The production employee route is `/employee`. It renders the checked-in mobile-first HTML from `OrchidHRM/employee_mobileApp.html` inside the authenticated employee frame. The reference HTML remains unchanged; interactive data binding is provided by `public/employee-controller.js`.

The authenticated Next.js employee frame loads `api.employee.myWorkspace` through Convex and sends the workspace to the same-origin iframe using the `ORCHID_EMPLOYEE_WORKSPACE` message. The controller accepts messages only from its parent window and the same origin.

## Payslip behavior

- The Payslips screen is populated from `workspace.wageRecords`.
- The backend query is employee-scoped through the authenticated user's linked employee profile. The client cannot supply an employee ID.
- Only wage records with `approved` or `locked` status are returned to the employee workspace.
- The employee can inspect the pay period, payslip reference, net payable amount, gross earnings, itemized earnings, itemized deductions, payable days/hours where available, and the net total.
- Historical wage records without itemized earnings/deductions show an explicit unavailable/none-itemized message rather than fabricated line items.
- Print / Save PDF opens a print-friendly payslip with employee identity, period, reference, earnings, deductions and net payable. The browser's print dialog can save it as PDF.
- The printed statement explicitly says that an approved payroll record is not proof of bank transfer.

## Data and authorization

- Source query: `api.employee.myWorkspace` in `convex/employee.ts`.
- UI binding: `src/components/employee-realtime-frame.tsx` and `public/employee-controller.js`.
- Original visual source: `OrchidHRM/employee_mobileApp.html`.
- Payroll record snapshots are generated by `convex/payroll.ts` and retain the calculation breakdown.
- Draft, pending, rejected, or otherwise unpublished records must never be exposed to employees.
- The query uses the authenticated identity and `users.employeeId`; no client-provided employee ID is trusted.

## QA checklist

- Employee A can see only Employee A's approved/locked payslips.
- Employee B cannot access Employee A's payslip by changing client data or record identifiers.
- Draft payroll is not shown before approval.
- Approved and locked payroll records appear after the realtime workspace refresh.
- Earnings, deductions, gross and net values match the admin payroll record exactly.
- Historical records without a snapshot do not display invented breakdowns.
- Print / Save PDF produces a readable mobile- and desktop-friendly statement.
- Popup blocking is handled with a clear message.
- Unauthenticated, inactive, unlinked and non-employee accounts cannot access the employee route.
